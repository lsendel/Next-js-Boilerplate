# Integrations

The Next.js Boilerplate includes production-ready integrations with best-in-class services.

## Overview

Pre-integrated and configured:

- 🐛 **[Sentry](/integrations/sentry)** - Error monitoring and performance tracking
- 📊 **[PostHog](/integrations/posthog)** - Product analytics and feature flags
- 🛡️ **[Arcjet](/integrations/arcjet)** - Security, bot detection, rate limiting
- 📝 **[LogTape](/integrations/logtape)** - Structured logging
- 📈 **[Better Stack](/integrations/better-stack)** - Log management and uptime monitoring
- 🔍 **[Checkly](/integrations/checkly)** - Synthetic monitoring as code
- 🌍 **[Crowdin](/integrations/crowdin)** - Translation management

## Quick Setup

Most integrations are already configured - you just need to add API keys:

```bash
# apps/web/.env.local
SENTRY_DSN=https://your-sentry-dsn
NEXT_PUBLIC_POSTHOG_KEY=phc_your_key
ARCJET_KEY=your_arcjet_key
NEXT_PUBLIC_BETTER_STACK_SOURCE_TOKEN=your_token
```

## Environment Variables

### Required for Production

```bash
# Error Monitoring
SENTRY_DSN=https://your-sentry-dsn
NEXT_PUBLIC_SENTRY_DSN=https://your-sentry-dsn
SENTRY_AUTH_TOKEN=your_auth_token
SENTRY_ORG=your-org
SENTRY_PROJECT=your-project

# Analytics
NEXT_PUBLIC_POSTHOG_KEY=phc_your_key
NEXT_PUBLIC_POSTHOG_HOST=https://app.posthog.com

# Security
ARCJET_KEY=your_arcjet_key
ARCJET_MODE=LIVE

# Logging
NEXT_PUBLIC_BETTER_STACK_SOURCE_TOKEN=your_token

# Optional: Google Analytics
NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX
```

### Optional for CI/CD

```bash
# Checkly (synthetic monitoring)
CHECKLY_API_KEY=your_checkly_key
CHECKLY_ACCOUNT_ID=your_account_id

# Crowdin (translations)
CROWDIN_PROJECT_ID=your_project_id
CROWDIN_PERSONAL_TOKEN=your_personal_token
```

## Best Practices

### Error Monitoring

✅ **DO:**
- Set up error alerts
- Configure release tracking
- Use breadcrumbs for context
- Filter out expected errors
- Set up source maps

❌ **DON'T:**
- Log sensitive data
- Ignore error thresholds
- Skip production testing

### Analytics

✅ **DO:**
- Identify users
- Track key events
- Use feature flags
- Respect privacy (GDPR)
- Test tracking locally

❌ **DON'T:**
- Track PII without consent
- Create too many events
- Forget to anonymize data

### Logging

✅ **DO:**
- Use appropriate log levels
- Include context (userId, etc.)
- Structure logs (JSON)
- Rotate log files
- Set up alerts

❌ **DON'T:**
- Log passwords or secrets
- Use console.log in production
- Create excessive logs
- Ignore log analysis

## Cost Optimization

### Free Tiers

- **Sentry:** 5,000 errors/month
- **PostHog:** 1M events/month
- **Arcjet:** Generous free tier
- **Better Stack:** 1GB logs/month
- **Checkly:** 150 checks/month
- **Crowdin:** Free for open source

### Reduce Costs

1. **Sample data** - Don't send everything
2. **Filter noise** - Ignore known errors
3. **Set retention** - Delete old data
4. **Use environments** - Dev/staging separate

## Troubleshooting

### Sentry Not Capturing Errors

1. Check `SENTRY_DSN` is set
2. Verify source maps uploaded
3. Check error filters
4. Test with `Sentry.captureException(new Error('Test'))`

### PostHog Events Not Showing

1. Check API key is valid
2. Verify host URL correct
3. Check browser console for errors
4. Events may take a few minutes to appear

### Arcjet Blocking Legitimate Traffic

1. Check bot categories configured
2. Verify rate limits appropriate
3. Review decision logs
4. Adjust rules in `apps/web/src/middleware.ts`
