# Better Stack

Log management, uptime monitoring, and incident management platform.

## Overview

Better Stack provides comprehensive operational monitoring:

- **Log Management** - Centralized log aggregation and search
- **Uptime Monitoring** - Website and API availability checks
- **Incident Management** - Alert routing and on-call scheduling
- **Status Pages** - Public status communication
- **Real-time Search** - Fast log queries and analysis
- **Dashboards** - Custom visualizations and metrics

## Quick Setup

### 1. Create Better Stack Account

Sign up at [betterstack.com](https://betterstack.com):

1. Create a new account
2. Create a **Log Source** for your application
3. Copy the **Source Token**

### 2. Configure Environment Variables

```bash
# apps/web/.env.local

NEXT_PUBLIC_BETTER_STACK_SOURCE_TOKEN=your_source_token_here
```

### 3. Configure LogTape Integration

LogTape is already configured to send logs to Better Stack:

```typescript
// libs/Logger.ts
import { getBetterStackSink } from '@logtape/logtape'

await configure({
  sinks: {
    console: getConsoleSink(),
    betterStack: getBetterStackSink({
      sourceToken: process.env.NEXT_PUBLIC_BETTER_STACK_SOURCE_TOKEN!,
      level: 'info',
    }),
  },
  loggers: [
    {
      category: 'app',
      level: 'debug',
      sinks: ['console', 'betterStack'],
    },
  ],
})
```

### 4. Verify Logs

```bash
# Start your app
pnpm --filter web dev

# Trigger some logs
# Visit: http://localhost:3000

# Check Better Stack dashboard
# Logs should appear within seconds
```

## Log Management

### View Logs

1. **Go to [logs.betterstack.com](https://logs.betterstack.com)**
2. **Select your source**
3. **View live tail** - Real-time log stream
4. **Search logs** - Query historical logs

### Search Logs

```
# Search by level
level:error

# Search by message
message:"User created"

# Search by field
userId:user_123

# Combine filters
level:error AND userId:user_123

# Time range
level:error last 1h

# Regular expressions
message:/payment.*failed/i
```

### Example Queries

```
# All errors in last hour
level:error last 1h

# Slow API requests
duration:>1000 AND path:/api/*

# Failed payments
event:payment.failed

# User activity
userId:user_123 last 24h

# Database errors
message:"database" AND level:error
```

## Structured Logging

### Send Structured Logs

```typescript
import { logger } from '@/libs/Logger'

// Automatically sent to Better Stack
logger.info('User action', {
  userId: user.id,
  action: 'purchase',
  product: 'premium',
  amount: 99.99,
  timestamp: new Date(),
})
```

### Best Log Structure

```typescript
logger.info('Operation completed', {
  // Event type
  event: 'payment.completed',

  // User context
  userId: user.id,
  email: user.email,

  // Operation details
  orderId: order.id,
  amount: 99.99,
  currency: 'USD',

  // Performance
  duration: 123,

  // Additional context
  source: 'web',
  version: '1.0.0',
})
```

## Uptime Monitoring

1. **Go to Better Stack → Uptime**
2. **Click "Create Monitor"**
3. **Configure:**
   - URL: `https://yourapp.com`


## Alerts

1. **Better Stack → Alerts → Policies**
2. **Create policy:**
   - Name: "Production Errors"
   - Conditions: `level:error`

### Alert Channels

**Email:**
```

```

**Slack:**
```

```

**PagerDuty:**
```

```

**Webhook:**

### Alert Examples

**Error Rate Alert:**

## Integration with Other Services

### Sentry Integration

Forward Sentry errors to Better Stack:

```typescript
// sentry.server.config.ts
Sentry.init({
  dsn: process.env.SENTRY_DSN,
  beforeSend(event) {
    // Send to Better Stack via logger
    logger.error('Sentry error', {
      error: event.message,
      tags: event.tags,
      level: event.level,
    })

    return event
  },
})
```

## Best Practices

✅ **DO:**

- Use structured logging (JSON)
- Include context in every log
- Set up alerts for critical errors
- Create dashboards for key metrics
- Monitor uptime from multiple regions
- Configure escalation policies
- Use status pages for transparency
- Archive old logs to reduce costs

❌ **DON'T:**

- Log sensitive data (passwords, tokens)
- Over-alert (alert fatigue)
- Skip log rotation
- Ignore retention limits
- Forget to test alerts
- Mix dev and prod logs
- Skip incident post-mortems

## Troubleshooting

### Logs Not Appearing

1. **Check source token:**
   ```bash
   echo $NEXT_PUBLIC_BETTER_STACK_SOURCE_TOKEN
   ```

2. **Verify LogTape configuration:**
   ```typescript
   // Should include betterStack sink
   sinks: ['console', 'betterStack']
   ```

3. **Check network connectivity:**
   - Firewall rules
   - Outbound HTTPS allowed

4. **Test manually:**
   ```typescript
   logger.info('Test log', { test: true })
   ```

### High Log Volume

1. **Reduce log level:**
   ```typescript
   level: 'warn'  // Skip info/debug
   ```

2. **Filter unnecessary logs:**
   ```typescript
   filters: [
     (log) => !log.message.includes('health_check')
   ]
   ```

3. **Sample high-volume logs:**
   ```typescript
   if (Math.random() < 0.1) {  // 10% sampling
     logger.debug('Debug log')
   }
   ```

### Alerts Not Firing

1. **Check alert policy conditions**
2. **Verify data is being logged:**
   ```
   level:error last 1h  // Should show errors
   ```
3. **Test alert manually:**
   - Trigger condition
   - Verify channel receives alert

### Slow Searches

1. **Use time ranges:**
   ```
   level:error last 1h  // Faster than "last 7d"
   ```

2. **Index frequently searched fields**
3. **Use specific queries:**
   ```
   userId:user_123  // Better than wildcard
   ```

## Cost Optimization

### Free Tier Features

- 1 GB logs/month
- 7 days retention
- Unlimited monitors
- Unlimited dashboards
- Unlimited team members

### Reduce Costs

1. **Sample logs:**
   ```typescript
   // Only log 10% of requests
   if (Math.random() < 0.1) {
     logger.info('Request', { ... })
   }
   ```

2. **Increase log level:**
   ```typescript
   level: 'warn'  // Skip info/debug in production
   ```

3. **Filter noise:**
   ```typescript
   // Skip health checks
   if (path !== '/health') {
     logger.info('Request', { ... })
   }
   ```

4. **Reduce retention:**
   - Archive to S3 after 7 days
   - Keep only errors for 30 days
